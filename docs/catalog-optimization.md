## 2. 范围与实施原则

- **下架不删除。** 历史订单继续使用下单时的商品及报价快照；不能因当前商品改名、改价、换图或下架而改写历史订单、支付、退款或库存流水。
- **库存走运营接口和流水。** 不直接覆盖数据库余额，不通过重置库存、清空订单或清理流水使验收通过；重跑使用原入库操作编号。
- **商品与活动分别管理。** B 上架不等于具备可用活动；须确认 A 接收正确版本，并核对活动资格、应付金额、目标人数、活动区间及团队有效期。
- **逐步替换首页。** 先保证新商品可用，再下架已确认样本；新商品未就绪时保留原可用展示商品，避免首页短时间无商品。
- **按精确归属收尾。** 仅处理明确记录的环境、批次和商品 ID；名称包含 `test`、`UX05` 等只能作人工排查线索，不能直接生成批量下架条件。
- **先证据，后收尾。** 成功和失败批次都保存原商品 ID、订单 ID、请求结果及原操作编号；不因失败另建替代订单或新入库键。
- **已有订单自然收敛。** 下架仅阻止新的购买，不删除进行中订单，不强改团队终态、到期时间、支付或退款；已有查询、付款资格核对、取消和退款恢复仍按原服务端规则执行。
- **展示商品与验收商品分开。** 正常中文演示商品主要做只读检查；需要新交易、缺货、故意坏图等写入场景时，使用本批专用验收商品。演示商品不承诺真实扣款、发货或售后服务。
- **环境和历史冻结保持。** 不复制 UX 数据库或测试卷到主站，不覆盖 TD-06／ST／UX 已封存清单；新资源需要发布时建立新的可追踪产物。

本轮不新增购物车、多 SKU、真实支付、发货履约、部分退款、搜索推荐或通用活动管理平台。若现有接口或恢复路径确有缺口，在对应 CAT 阶段记录问题、最小改动和回归范围，不将扩大能力默认为已授权需求。

## 5. 商品清单与批次记录约定

本节定义批次记录字段；CAT-01.1 已产生真实只读清单，CAT-01.2 再冻结新内容，不填充虚构商品 ID。后续 UX 与主站分别产生执行记录，不共享商品或交易标识。

| 记录 | 必须包含 |
| --- | --- |
| 执行身份 | 阶段、批次、环境、项目／域名、执行时间、工具版本、运营身份的非敏感标识 |

| 库存与活动 | 原入库 operationId／请求体／结果／流水；活动、折扣、渠道绑定和原配置校验结果 |

## 6. 风险与恢复边界

| 风险 | 防护及验收依据 |
| --- | --- |
| 历史商品误判或盘点过期 | 精确 ID＋批次证据＋执行前重读；待核对默认保留 |
| 商品编辑覆盖、版本变化或同步乱序 | 完整字段及乐观锁；核对最终在售版本和可信确认，不接受过期回执 |
| 创建结果未知、重复入库或重复资金操作 | 先持久化原身份／键和请求；原记录查询／受控原键重试；不自动制造替代事实 |

| 图片失效或资源尚未发布 | 来源和哈希、实际 HTTP／浏览器加载、图片占位、手机／桌面检查及新产物部署 |

| 主站首页空窗、误清正常商品 | 先新后旧、分批执行；收尾只选本批专用样本；保留可用展示集 |
| 中断后数据被旧备份覆盖 | 保存最新事实和原键；必要时兼容退包并使用当前数据，不降级数据库或覆盖在线卷 |

商品变更的补偿同样走运营接口及新版本；不能回滚版本号。入库过量须查清原流水后制定合法库存运营操作，不能重置余额。A 活动变更仅按已冻结配置流程处理，不影响历史成交事实。

若仅资料整理且无需改代码／资源，不强制构建新业务镜像；若新增静态图片或修改前端／工具，则执行对应检查和必要发布。健康检查保持只读或既有无业务副作用的探针，不创建商品、入库或新订单。
